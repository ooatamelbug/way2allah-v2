## Scope

Prior to this task: `ADMIN_FUNCTIONAL_MIGRATION_COMPLETE`, `ADMIN_VISUAL_PARITY_PENDING` — the functional `/admincp/` login+dashboard+11 feature modules worked, but every view rendered as bare unstyled HTML (no CSS, no header, no sidebar, no footer), not resembling the real legacy AdminCP.

This task reconstructed the real legacy AdminCP shell (Metronic layout4, RTL) from source, separated it from `admincp/home.php`'s confirmed 100%-demo dashboard content (zero DB queries — hardcoded stats, fake charts, fake activity feed, fake regional map), and reconciled every migrated admin page against the reconstructed shell — without touching authentication, permissions, business logic, or any already-migrated module's data/behavior.

## What changed

- `resources/views/layouts/admin.blade.php` — full rebuild: real header (logo, user identity, real POST logout), real permission-aware sidebar (reusing `AdminDashboardModules`, not a duplicate permission map), real footer. **Correction (2026-08-22, same day, AdminCP Final Page-Level Visual-Parity Verification):** this layout no longer auto-wraps page content in one shared generic portlet — that was reviewed and found to be an unjustified simplification wherever a legacy page had more than one real portlet (`broadcasting/edit_stream.php` and 8+ other pages, confirmed by source). The layout now owns only the shell/content container; every feature view wraps its own content in one or more `<x-admin-portlet>` components matching legacy's real per-page portlet count/caption/color. - `resources/views/layouts/admin-guest.blade.php` (new) — the login-page-only frame (legacy `w2a__login.php`'s real visual design: centered logo, login-4 Metronic theme).

- `app/Domain/Admin/Support/AdminDashboardModules.php` — added a real, source-grounded `icon` per module (from each module's own legacy `menu.php`, where one exists).
