## 9. Safe cPanel ZIP creation procedure

Commit the intended release changes first. `git diff` does not include
untracked files, so inspect `git status --short` and make sure no required new
file is omitted. Preserve unrelated user changes.

Set exact full commit hashes in the following procedure. It stages copies in a
temporary directory, maps `public/` to `newapp/`, maps everything else to
`laravel-app/`, and verifies the ZIP manifest byte-for-byte against Git.
The target commit must be the currently checked-out, clean tree because the
copy step deliberately reads the checked-out files.

```bash
cd /Users/dash/work/way2allah-v2

DEPLOYED_COMMIT=<full-confirmed-production-commit>
TARGET_COMMIT=<full-tested-target-commit>
PACKAGE_NAME=way2allah-v2-cpanel-$(date +%F).zip
PACKAGE_OUTPUT="/Users/dash/work/way2allah-v2/${PACKAGE_NAME}"
PACKAGE_STAGE=$(mktemp -d /private/tmp/way2allah-cpanel.XXXXXX)
EXPECTED_MANIFEST="${PACKAGE_STAGE}/expected.txt"
ACTUAL_MANIFEST="${PACKAGE_STAGE}/actual.txt"

test ! -e "${PACKAGE_OUTPUT}"
test "$(git rev-parse HEAD)" = "${TARGET_COMMIT}"
git diff --quiet
git diff --cached --quiet

git diff --name-status "${DEPLOYED_COMMIT}..${TARGET_COMMIT}"
```

Stop here if the status output contains `D` or `R`. An overwrite-only ZIP
cannot delete an old server file. For a deletion, prepare a separate explicit
deletion list for cPanel. For a rename, include the new file and list the old
server path for deletion. Never hide these operations.

If the diff contains only `A`, `C`, `M`, or `T` entries:

```bash
git diff --name-only --diff-filter=ACMT \
  "${DEPLOYED_COMMIT}..${TARGET_COMMIT}" |
while IFS= read -r REPO_FILE; do
    case "${REPO_FILE}" in
        public/*)
            PACKAGE_FILE="${PACKAGE_STAGE}/newapp/${REPO_FILE#public/}"
            ;;
        *)
            PACKAGE_FILE="${PACKAGE_STAGE}/laravel-app/${REPO_FILE}"
            ;;
    esac

    mkdir -p "$(dirname "${PACKAGE_FILE}")"
    cp -p "${REPO_FILE}" "${PACKAGE_FILE}"
done

(
    cd "${PACKAGE_STAGE}"
    zip -q -r "${PACKAGE_OUTPUT}" newapp laravel-app
)

git diff --name-only --diff-filter=ACMT \
  "${DEPLOYED_COMMIT}..${TARGET_COMMIT}" |
awk '{
    if ($0 ~ /^public\//) {
        sub(/^public\//, "")
        print "newapp/" $0
    } else {
        print "laravel-app/" $0
    }
}' | sort > "${EXPECTED_MANIFEST}"

unzip -Z1 "${PACKAGE_OUTPUT}" |
awk '!/\/$/' |
sort > "${ACTUAL_MANIFEST}"

diff -u "${EXPECTED_MANIFEST}" "${ACTUAL_MANIFEST}"
unzip -t "${PACKAGE_OUTPUT}"
shasum -a 256 "${PACKAGE_OUTPUT}"
```

The `diff -u` command must produce no output, `unzip -t` must report no
errors, and the ZIP listing must have only `newapp/` and `laravel-app/` at its
top level.

The repository ignores archives named
`way2allah-v2-ui-enhanced-v2-cpanel-*.zip`. For a new naming pattern, check
`git status` and never commit deployment archives unless the user explicitly
requests it.

## 12. Known live infrastructure issue

The live site sometimes returned HTTP 500 and sometimes loaded normally. At
the same time, the cPanel terminal showed:

```text
bash: fork: retry: No child processes
bash: fork: Resource temporarily unavailable
```

This is strong evidence that the hosting account hit a process limit such as
NPROC or Entry Processes. A sample of 12 requests later returned 12 successful
HTTP 200 responses, reinforcing that the failure was intermittent rather than
a deterministic Blade/CSS bug.

Actions for the hosting owner:

- Check cPanel **Metrics → Resource Usage** for NPROC, Entry Process, CPU,
  memory, and I/O faults at the timestamps of the 500s.
- Inspect PHP-FPM workers, cron jobs, queue workers, and abandoned processes.
- Review `/home/w2acp/laravel-app/storage/logs/laravel.log` and the web server
  error log for the same timestamp.
- Ask the hosting provider to restart stuck PHP/shell processes and explain or
  raise the account limits if they are too low.
- Avoid running duplicate persistent `queue:listen` processes on shared
  hosting. Confirm how queues are intended to run in production.

Browser console messages such as AddThis DNS failures, SoundCloud iframe
warnings, or browser-extension `Web2MD` messages do not explain a server-side
HTTP 500. AddThis was subsequently removed from the shared layout.

Performance logs, when enabled, live at:

```text
storage/logs/performance-YYYY-MM-DD.log
storage/logs/slow-sql-YYYY-MM-DD.log
```

See `docs/operations/performance-monitoring.md` for thresholds and correlation
by request ID.

globally. Runtime files actually referenced by tracked Blade/CSS/JS are
unignored one file at a time in `.gitignore`. This is intentional: do not

Do not mass-add thousands of unused theme/demo files. Preserve existing user
